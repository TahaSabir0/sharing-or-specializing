## §1. Alex's 9-config learned-router cross-validation (reported 2026-08-05, reviewed 2026-08-19)

**Setup (as reported).** Qwen3-VL-8B-Instruct, **frozen** backbone + **frozen** LoRAs; only a small
router MLP is trained. Features = GLiClass **task** scores (from the question) ⊕ MedSigLIP **modality**

### §1d. Review (2026-08-19) — what this does and does not establish

**The mechanism is plausible and worth crediting.** "Task neighbors" share an **output format**
(det/count/reg all emit numbers; ML/cls both emit label sets), while report-gen (free text) and cls
(single label) have unique formats and are corrupted by merging. That is exactly our PGF finding that
**negative transfer = output-format lock-in** (`stats/12`) — configs 1–7 independently reproduce it, and
config 8 is the natural corollary ("merge only where formats match"). **The negative half of this study
is its strongest, most publishable content.**

**Four reasons config 9 is NOT adoptable on these numbers:**

1. **⚠️⚠️ Self-inconsistency, blocking.** On *classification rows* config 9 executes "cls alone (config-8
   rule) + top-1 modality merged" — the **same computation as config 4**. Yet cls = **0.5757** (config 4)
   vs **0.6008** (config 9): **same recipe, same rows, +0.025 apart.** Either the configs differ in an
   undocumented way, or the harness carries ~0.025 run-to-run variance — which would **swamp the +0.0084
   headline**. Must be resolved before anything else.
2. **⚠️ The baseline is ~0.20 F1 below production.** Config-1 here is cls 0.5924 / **ML 0.2780**; our
   deployed system on the same split is cls ~0.70 / **ML 0.4816**, and his own §1b table has config 1 at
   ML 0.4529. Gains over a weak base routinely fail to survive a strong one — the ML rank bump measured
   +0.05 at 768²/A′ and delivered **~0** on the board ([[project-recipe-screen-overpredicts]]).
3. **⚠️ Selection on the scoring split.** Configs 8/9 *are* the finding extracted from configs 1–7 on
   `validation-public`, then scored on `validation-public`. That is not validation.
4. **⚠️ The ML gain is on the wrong dataset for the board.** `validation-public` ML is **chestdr only**;
   the board's ML is **periapical only** (`stats/22`). The +0.0395 says nothing about the board ML gap.
   *(Note the further re-scope in `stats/6 §8`: periapical is the ML slice on the **test** path too.)*

**Deployment cost, if it were ever adopted:** config 9 requires **MedSigLIP running on every image**
inside the submission container plus per-case adapter merging — an extra model and an extra failure
surface, in an image that has not yet been rebuilt. Runtime itself is not the constraint (`stats/13 §2`:
we sit at 0.56× the baseline).

**DECISION (2026-08-19): not adopted.** The one run that would settle it — and which Alex already scoped
as `experiments/learned_router_cv/scaled_ab/` but left **empty** — is **config 9 vs config 1 on
`true_test`, with the deployed A∪B `*_s1337` 2048² adapters, greedy**: strong base, all datasets, a split
the gating rule was not tuned on. If it holds there it earns a board slot; if not, §1b + §1c stand as a
clean negative result corroborating `stats/12`.
