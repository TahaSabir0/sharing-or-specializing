# 12. Task-Transfer Stats — PGF matrix over our per-task adapters

Applies **Sachdeva et al., "Understanding Task Transfer in Vision-Language Models"**
(arXiv:2511.18787) to our own build. Narrative + framing: `PROGRESS.md` 2026-07-09; design +
paper-section draft: `report/FLARE2026_task_transfer.md`; raw per-question files:
`predictions/task_transfer/`. See [[project_task-transfer-pgf]].

## Setup (read before comparing any number)

- **Split:** `internal_splits_v2/true_test.jsonl` (4,574 rows), held-out for the `_s1337` adapters
  (trained on A∪B) → leak-free. `general_full` was **excluded** (it trained on true_test → would leak);
  the general row uses **`general_A_s1337`** (A-alone, leak-safe).
- **Backbone:** Qwen3-VL-8B-Instruct, 4-bit, per-task QLoRA r8 seed 1337 (`saves/qwen3_final/*_s1337`).
- **Controlled decode (KEY):** every cell uses `--prompt_variant none` + **native DeepStack [8,16,24]**,
  target-specific `max_new_tokens` (cls 512, counting 64, detection 512, regression 64, ML 128). This is
  deliberately NOT the deployed `eval_full_system.sh` knobs (which add CoT/medical_cot/DeepStack-thirds) —
  we hold the prompt path fixed and vary ONLY the adapter, so a cell measures the *adapter's* transfer.
- **Metric:** per-dataset **macro** of each task's headline metric (`score_single` `task_macro`):
  classification = balanced acc ↑, multi-label = micro-F1 ↑, detection = F1@IoU>0.5 ↑,
  counting/regression = MAE ↓.
- **Rows = source adapters** (7) + **base** (zero-shot, no PEFT — the PGF anchor, via `--adapter_path none`).
  `reportgen`'s own task (report_generation) and `general_A` are not single-task targets → reportgen has
  no in-grid diagonal; general_A is a reference row only. Report-gen as a *target* (CRIMSON) is a deferred
  phase 2 (not in this matrix).

**FLARE-adapted PGF** (fraction of the gap-to-perfection closed by the row-adapter on the col-task):
- higher-better (cls, det, ML), ceiling U=1: `mu = (m_i - m_base)/(1 - m_base + eps)`
- MAE (counting, regression), gap-to-zero-error: `mu = (MAE_base - MAE_i)/(MAE_base + eps)`
- eps = 1e-6. Positive mu = improvement in every cell. **Asymmetry caveat (per the paper): positive mu is
  capped at 1, negative mu is unbounded** — the MAE blow-ups below are real but dominate any naive mean.

## §4 — Transfer structure (off-diagonal, single-task sources only)

- **Diagonal (direct supervision) — all strongly positive:** cls 0.65, counting 0.88, detection 0.90,
  regression 0.83, ML 0.34. Finetuning closes 34–90% of the gap to perfection on the own task. ML lowest
  → consistent with the capability-bound multi-label finding ([[project_rebalancing-low-ceiling]]).
- **`detection` = pirate + sieve.** As a source it is ≤0 on all 4 other tasks; as a target every non-det
  source is ~0 (malformed boxes). Must stay isolated.
- **Mild positive cluster: {counting, regression, multilabel}.** These numeric/format-compatible tasks
  nudge each other up (regression→counting +0.16, counting→regression +0.38, both →ML +0.14; multilabel
  →regression +0.26). Low-risk candidate for adapter merging to save budget.
- **`cls_bare` helps only classification** (and general). Near-zero or catastrophic elsewhere.
- **`general_A` (the mix) is a strong generalist that avoids the collapse:** near-specialist on 3/5 tasks
  (detection 0.88 vs 0.90, regression 0.81 vs 0.83, counting 0.78 vs 0.88), clearly beaten only on **cls
  (0.59 vs 0.65)** and **ML (0.30 vs 0.34)**, and — critically — 0 malformed. So specialists earn their
  keep mainly on cls (~50% of ranking) and ML; the mix is competitive elsewhere without format collisions.

## §5 — Takeaway

**Negative transfer in our open-ended VLM is overwhelmingly output-format lock-in** — a specialist forces
its own answer format, which is malformed/absurd on other tasks. This mechanism is invisible in the
paper's MCQ setting (constrained output space) → our genuine open-ended extension, and a quantitative
justification of the **routed architecture** (routing guarantees each question hits the format-matched
adapter, dodging the exact collapse the off-diagonal reveals). Ties to [[project_format-not-bottleneck]].

**Deferred / open:** report-gen (CRIMSON) target column (phase 2, running 2026-07-09); a `validation-public`
second-split pass for robustness.

## §6 — Capability-only view (resolves the unbounded-negative-PGF problem)

**Problem.** Raw PGF's negative side is unbounded (paper's asymmetry: positive capped at +1, negative → −(m−1)),
so a few **format-collapse** cells — where a specialist emits its *own* answer format on another task, e.g.
`cls_bare → counting` (MAE 14,989 → raw PGF **−119**), `reportgen → counting` (**−26**) — dominate any naive
transferability mean and make the donor/pirate aggregate unreadable. These are output-format artifacts, NOT
graded capability loss.

**Fix (two moves).** (1) **Flag format-collapse cells** and exclude them from capability aggregates: an
off-diagonal cell is a collapse iff `raw PGF ≤ −1` (≥100% of baseline headroom erased / MAE ≥ doubled) **OR**
malformed-rate ≥ 50%. (2) For the remaining cells, aggregate μ **clipped to [−1, +1]** (bounds the negative
side to match PGF's natural +1 positive cap). Reproducible: `predictions/task_transfer/compute_pgf.py`.

**The 4 collapse cells (the format lock-in, quantified):**

| cell | raw PGF | malformed | why |
|---|---|---|---|
| cls_bare → counting | −119.24 | 0% | emits a class label → counting MAE 14,989 vs base 125 |
| reportgen → counting | −25.90 | 0% | emits a report → counting MAE 3,353 |
| detection → regression | −1.33 | 0% | emits a box → regression MAE 143 vs base 61 |
| regression → detection | −0.01 | **92%** | emits a bare number → 540/588 malformed boxes |

**Capability-only transferability** (off-diagonal, collapses excluded, clipped) — naive raw mean shown for contrast:

| source | naive raw mean | **capability-only mean** | read |
|---|---|---|---|
| counting | +0.14 | **+0.138** | **donor** (numeric) |
| regression | +0.09 | **+0.121** | **donor** (numeric) |
| cls_bare | −29.76 | +0.063 | ~neutral once collapse removed |
| reportgen | −5.16 | +0.030 | ~neutral once collapse removed |
| multilabel | +0.00 | +0.001 | neutral |
| detection | −0.46 | **−0.165** | **pirate** (negative even excluding its 1 collapse) |

**Capability-only malleability** (per target):

| target | capability-only mean | read |
|---|---|---|
| regression | **+0.252** | **sponge** (absorbs from counting/others) |
| multi-label classification | +0.043 | mildly malleable |
| classification | +0.028 | ~inert (only its own adapter helps) |
| detection | −0.008 | inert |
| counting | **−0.201** | **sieve** (hard to help; 2 collapses excluded) |

**Refined structure (supersedes the §4 first-pass "cluster" wording):**
- **Donor pair = {counting, regression}** — the numeric-output tasks mutually transfer (`counting→regression`
  +0.38, `regression→counting` +0.16) and both lift ML (+0.14 each). This is the one genuine positive-transfer
  signal. Note `multilabel→counting` is **−0.29**, so it is NOT a clean 3-way clique — the core is the numeric pair.
- **detection = pirate + sieve**, confirmed *after* removing format collapse (transferability −0.165, malleability
  −0.008) — genuinely isolated, not just a format artifact.
- **regression = top sponge; counting = sieve.** classification/ML absorb transfer only from their own specialist
  (+ general) → capability-bound, consistent with [[project_rebalancing-low-ceiling]].

**Takeaway for the paper:** the capability-only view shows that once you strip the format-lock-in collapses, genuine
cross-task capability transfer is small and confined to the numeric {counting, regression}→{regression, ML} pathway;
detection is a true pirate. So the negative-transfer story is TWO layers — (i) dominant output-format lock-in
(the collapses, → routing), and (ii) a faint residual capability-transfer structure underneath (numeric-task affinity).

## §7 — Report-generation column (CRIMSON, the 6th target) — DONE 2026-07-14

| source → report_gen | CRIMSON | prose-rate | PGF | class |
|---|---|---|---|---|
| reportgen (own task) | 0.805 | 99% | +0.756* | direct supervision |
| general_A (mix) | 0.805 | 99% | +0.756 | capability (ties the specialist) |
| base (zero-shot) | 0.202 | 100% | 0.000 | anchor |
| cls_bare | −0.077 | 96% | −0.350 | capability (valid prose, bad report) |
| multilabel | 0.078 | 98% | −0.156 | capability (valid prose, bad report) |
| counting | 0.454 | 17% | (+0.315) | **COLLAPSE** (mostly numbers) |
| detection | **0.816** | **0%** | (+0.769) | **COLLAPSE** (all boxes — see below) |
| regression | 0.051 | 31% | (−0.189) | **COLLAPSE** (mostly numbers) |

**★ CRIMSON is unreliable on wrong-format output — a methodological finding.** The `detection` adapter emits
**bounding boxes** (`[[0,23,167,198]]`) on 100% of report-gen questions, yet the CRIMSON LLM-judge scored it
**0.816 — ABOVE the actual report specialist (0.805).** The judge does not penalise non-report output. Therefore
report-gen collapse **cannot** be detected by the metric (unlike the score_single tasks, where malformed-rate/PGF≤−1
work); it must be gated by **output format (prose-rate < 90% ⇒ collapse)**. Under that gate, 3 sources
(counting/detection/regression) are format collapses and excluded; their CRIMSON scores are artifacts, not transfer.
Paper value: (a) reinforces the output-format-lock-in thesis into a 6th task, and (b) a genuine caveat on LLM-as-judge
report metrics for cross-task analysis.

**Capability-only aggregates, now over all 6 targets** (report-gen collapses excluded):

| source | transferability (6-target) | | target | malleability |
|---|---|---|---|---|
| counting | **+0.138** (donor) | | regression | **+0.252** (sponge) |
| regression | **+0.121** (donor) | | multi-label | +0.043 |
| reportgen | +0.030 | | classification | +0.028 |

Adding report-gen leaves the donor pair {counting, regression} and pirate (detection) intact; it nudges cls_bare and

(0.805), reinforcing "the mix is a strong generalist" across all 6 tasks. 7 collapse cells total now (§6's 4 + 3 report-gen).
