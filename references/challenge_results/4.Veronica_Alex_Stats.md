# Stats — Veronika's CoT prompts & Alex's task token

**Scope of this ledger.** All numbers we gather on **Veronika's CoT prompt variant** and **Alex's
predicted-task-token conditioning** — their original (pre-v2) reports *and* every retest we run on
the v2 pipeline. Append new runs here as they land (this is the numbers-of-record file for this scope;
narrative/decisions live in `PROGRESS.md`).

**How to read it.** Never compare across setups — only within a setup. Each block states its setup
(splits, adapter structure, training scale, metric aggregation). The headline metric is per-dataset
**macro** (the ChallengeR-faithful aggregation; see [[project-per-dataset-not-pooled-metric]]):
detection **F1 @ IoU>0.5 ↑**, counting/regression **MAE ↓**, classification **balanced accuracy ↑**,
multi-label **F1 ↑**.

#### Counting CoT — seed confirmation / error bars (2026-06-17, jobs 1278–1281, A→B, same setup as above)

Ran seeds 42 & 7 (cot+base paired) to put error bars on the A→B counting-CoT win (seed 1337 alone was the screen).

| seed | base MAE | cot MAE | Δ (cot−base) |
|---|---|---|---|
| 1337 | 40.99 | 35.69 | −5.30 (−13%) |
| 42 | 35.75 | 33.96 | −1.79 (−5%) |
| 7 | 36.52 | 32.71 | −3.81 (−10%) |
| **mean** | **37.75** | **34.12** | **−3.63 (−9.6%)** |

**Verdict: CoT wins all 3 seeds (direction robust); mean ΔMAE = −3.63 (~−10%), range −1.8 to −5.3.** Base is seed-noisy
(36.5–41.0) and CoT is tighter (32.7–35.7) → the seed-1337 −13% was the high end; the honest reportable number is
**≈ −3.6 ± 1.8 MAE**, not −13%. **Adopt CoT for the counting adapter** (modest but robust; counting is ~2% of ranking,
so a "bank the sure small win"). Raw: `~/ME-VLIP-tok/llama_factory_internvl/results/token/AB_counting_{cot,base}_s{1337,42,7}/`.

### Verdict (this screen)
- **+V (CoT) on counting = robust win** (both directions; counting answer-seed is empty so it's the CoT
  framing, not format-forcing). → **adopt CoT on the counting adapter.**
- **+V (CoT) on detection = wash** (sign-flip; `iugc` saturated ~0.99). → keep detection bare.
- **+A (task token) = wash everywhere** (slightly negative detection both ways; sign-flips counting). → **drop.**
- Trustworthy at single seed *because* both directions agree; sign-flips are the noise signature.

## §1b. CoT counting RE-VALIDATED on Qwen3-VL → DROPPED (2026-06-24)

**Setup:** branch `Taha/final-pipeline`, Qwen3-VL-8B-Instruct, `train_qwen3_count_cot.sh`, full A↔B (not prime),
seed 1337, k1 + markers, endo excluded. Counting specialist, bare vs CoT (`--prompt_variant cot`), both directions.
Metric = `task_macro.counting` MAE (lower better) via `infer_single_adapter.py --only_task counting` -> `score_single.py`.

| Direction | bare MAE | CoT MAE | delta (CoT-bare) |
|---|---|---|---|
| A->B | **33.65** | 35.05 | +1.40 (CoT worse) |
| B->A | **50.05** | 49.57 | -0.48 (CoT better) |
| avg | **41.85** | 42.31 | +0.46 (CoT worse) |

**Verdict: CoT sign-flips on Qwen3** (helps B->A, hurts A->B, slightly worse on average) -> fails the pre-registered
"lower MAE in both directions" adoption bar -> **counting adapter = bare on Qwen3.** The InternVL3 -3.6 MAE (section 1,
3 seeds) does NOT transfer -- backbone-dependent, like the task token (v1->v2) and packing (reversed on Qwen3).
Mechanism stays in-repo but unused in production.
