# Stats — Multi-image packing program (+ end-to-end adapter eval & ME-VLIP parity)

**Scope.** Every experiment in the multi-image **packing** line of work: does grouping a question's
images (vs last-year's flatten) help, and is the right `K` per-dataset? Plus the **end-to-end v2 adapter
eval** that deployed the resulting policy and the **ME-VLIP parity** check. Companion write-up:
`report/FLARE2026_dataset_report.pdf` §6–7 (the polished version). Raw per-question files:
`stats/predictions/results/{cls,cls_ofat,infer_rule,reportgen}/` and `stats/predictions/genadapter_eval/`.

**Headline.** Grouping helps **only** where a dataset's images are *complementary* — `neojaundice`
(3 body regions) gains +0.113 balanced accuracy at K=3. Everywhere redundant (CMMD near-dup views,
bcn20000 repeated shots, IU_XRay frontal+lateral) grouping is **inert**, so flatten (K=1) stays. The
per-dataset-K policy showed **no end-to-end benefit** in the full adapter eval → it was removed
(production flattens everything). We are at **parity with ME-VLIP** on classification (per-dataset macro
0.584 = 0.584).

> Metric note: classification is scored **per-dataset macro** (ChallengeR-faithful), not pooled — see
> [[project-per-dataset-not-pooled-metric]]. Where a raw file reports pooled balanced accuracy it is
> labelled as such and is the *lower*, misleading number; the macro is the figure of record.

## 13. Qwen3-VL backbone re-check — neojaundice K=3 vs K=1 (2026-06-20)

After the backbone switch InternVL3-8B → **Qwen3-VL-8B-Instruct**, re-test the *only* dataset that ever
earned grouping (neojaundice, +0.113 @ K=3 on InternVL3, §11c) to see if the win survives the new backbone.
Rationale: K is largely a *data* property, but Qwen3-VL uses ~8× fewer image tokens/image (grouping is
cheaper) + a different ViT/native multi-image path, so the cost-benefit *could* tilt. Lowest-favorable test.

**Setup.** Branch `Qwen/Qwen3-VL`, worktree `~/ME-VLIP-qwen3` (HEAD `05795ac`), env `flare-qwen3`, backbone
`~/models/Qwen3-VL-8B-Instruct`. Recipe = `flare_qwen3_vl_cls.yaml` (QLoRA r8, lr 2e-4, 3 ep, seed 1337,
4-bit, `Image-i:` markers), **identical across arms — only packing K varies.** neojaundice-only adapter
(other 10 cls datasets excluded at export+eval), n=268. **K1 flatten** (268→804 single-image rows, `--feed
first`) vs **K3 group** (268→268 three-image rows, `--feed group --dataset_k neojaundice=3`). Run **both
directions** A→B and B→A (jobs 1610/1611, both COMPLETED ~28 min). Script `scripts/qwen3_neo_packing.sh`.

| direction | K1 flatten | K3 group | Δ (K3 − K1) |
|---|---|---|---|
| A→B | 0.5123 | 0.4870 | **−0.025** |
| B→A | 0.5724 | 0.4541 | **−0.118** |

**Read: the InternVL3 win does NOT replicate — it REVERSES.** Grouping *hurts* in **both** directions
(−0.025 / −0.118), and the consistent sign across directions makes it a real effect, not noise (the
dual-direction design is the variance read the original single-direction §11c test lacked). On the most
favorable test case, Qwen3-VL prefers one-image-per-row — stuffing 3 marked images into a single sample
confuses it more than it helps, even though the cheaper token budget made grouping affordable.

**Decision: packing stays DEAD on Qwen3-VL — keep flatten-everything (K=1), `POLICY_DATASET_K={}`.** No
reason to re-check CMMD/IU_XRay: the premise (Qwen3-VL might fuse complementary images well enough to pay
off) is refuted at the one dataset where InternVL3 said yes. Artifacts:
`~/ME-VLIP-qwen3/llama_factory_internvl/results/qwen3/neo_{AB,BA}_{k1,k3}_s1337/metrics.json`.
See [[project_multi-image-packing]], [[project_backbone-survey]].

## 11c. Phase-1 packing sweep — SCALED OFAT (RUN #3, 2026-06-12)

Scaled the sweep to the **full A → full B** halves (not the 30% A′/B′ quick sets) and switched to a clean
**one-factor-at-a-time** design: train on full-A classification (endo + instance_detection excluded), and in
each arm flatten everything at K=1 **except one target dataset**, which is packed at its arm K. So each arm

| target | n(B) | baseline k1 | treatment | Δ vs baseline |

## 11f. IU_XRay report-generation packing test (K=1 vs K=2, 2026-06-12/13)

The last open row of the per-dataset-K program — and the one task scored by **GREEN**, not balanced accuracy,
so it needed a purpose-built harness (`scripts/eval_reportgen_arm.py` generation + `scripts/score_green.py`
GREEN scoring, decoupled; `train_reportgen_ofat.sh` driver). **GREEN is the only feasible report-gen metric**
— CRIMSON is implemented nowhere in our stack; GREEN (`StanfordAIMI/GREEN-radllama2-7b`, ~7B, staged to
`~/models`) is vendored + is what the repo's own `evaluation.py` uses. Run with `compute_summary_stats=False`
(skips the sentence-transformers clustering path → just the mean per-sample GREEN). green_score =
matched_findings / (matched + significant_errors) ∈ [0,1], higher better.

**Design (mirrors §11c OFAT).** IU_XRay = the **only** report_generation dataset, always X=2 (frontal + lateral
CXR). Train full-A report-gen, two arms, markers ON, epoch-matched (3 ep), seed 1337:
- **k1 flatten** (`--max_images 1`): each view → its own row carrying the same report (7,060 rows)
- **k2 group** (`--max_images 2`): frontal+lateral → one row → one report (3,530 rows)

Generate on a **deterministic n=1000 subsample of B's IU_XRay** (same subset both arms), GREEN-score. Jobs
796 (k1) / 797 (k2) trained + generated cleanly; GREEN scoring failed on a module-load `sentence_transformers`
import (fixed: made it lazy in `green_score/utils.py`), re-scored as job 806 (COMPLETED) on the saved
predictions — the decoupled scorer meant **no retrain/regenerate** was needed.

| arm | rows trained | GREEN mean (n=1000) | n_none |
|---|---|---|---|
| **k1 flatten** | 7,060 | **0.6379** | 0 |
| **k2 group** | 3,530 | **0.6394** | 0 |
| **Δ (k2 − k1)** | | **+0.0015** | |

**Read: grouping is INERT — a tie.** +0.0015 ≈ 0 (~0.1σ: per-sample GREEN std≈0.35, n=1000 ⇒ SEM≈0.011/arm,
combined SE on Δ ≈0.015). The prediction that complementary frontal+lateral views would help report-gen is
**refuted** at the GREEN level — the short region-targeted findings (e.g. "Visualized osseous structures…
without acute abnormality") are GREEN-equivalent from one view. n_none=0 both arms ⇒ no parse failures / empty
predictions (the generation + GREEN pipeline is clean).

**⚠️ Handicap note.** Every IU_XRay pair is X=2, so k1 had exactly **2× the rows → 2× gradient updates** —
a handicap *toward* k1. Pre-registered logic: a k2 win → conclusive; a k1 win → step-matched rerun. We got a
**tie** (k2 nominally +0.0015 *despite* the handicap), which triggers neither: when grouping is inert the
cheaper option wins the tiebreak, and a step-matched rerun changes no decision (same call as the CMMD/bcn
single-seed skip in §11c). **Decision: IU_XRay → K=1 (flatten); do NOT add to `POLICY_DATASET_K`.** Same
landing as CMMD + bcn20000 — neojaundice remains the *only* dataset where grouping earns signal.
Artifacts: `results/reportgen/{k1_s1337,k2_s1337}/metrics.json` (+ `green_per_sample.jsonl`).
