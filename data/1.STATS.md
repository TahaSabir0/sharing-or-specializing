# FLARE 2026 Task 3 — Dataset Stats & Experiments (compiled)

Single home for every dataset statistic and dataset-related diagnostic we've run, so we stop
re-deriving them. **Newest measurements get appended to the relevant section; Phase-1+ experiment
results go in §11.** Companion files in this folder: `FLARE2026_data_pipeline_v2.md` (the design /
decisions), `dataset_image_count_tables.html` (interactive heatmap of §3).

Scope: **2D set** — we are entering the 2D track only (the 3D CT-volume track is out of scope). Authoritative source for the
census is the **v2 splits** (`…/shared/internal_splits_v2/`, union = 51,154 QA pairs).

## 1. Headline numbers
- **51,154** classification-and-everything QA pairs (2D, cleaned v2 union), **50,996 images**, **19 datasets**, **8 modalities**, **7 task types in the data / 6 scored**.
- **64.6% single-image, 29.9% paired (X=2), 4.8% at 3–6, 0.7% at 7+.**
- Multi-image exists **only** in Classification + Report Generation (+ Mammography). The "weak" tasks (Detection, Counting, Regression) are **100% single-image**.
- Eval GPU = A6000 Ada 48 GB; Docker ≤35 GB; per-case runtime ≤1.5× baseline.

## 5. Scored vs. unscored tasks — Instance Detection is dead
*(2026-06-11, from EVAL.pdf + DATASET.pdf.)* The EVAL page defines metrics for **6** tasks; the data ships **7**. The 7th, **Instance Detection** (`Microscopy_chromosome`, **1,248** QA pairs in v2 / 1,785 images, Private), has **no metric** — a FLARE-2025 holdover (everyone scored 0). **Decision: drop from training + internal eval** (one-line export filter `task == instance_detection`); keep the Microscopy modality (its Counting subset is scored).

## 7. Tile / token load (the context-budget reality)
*(2026-06-11 / 0C. InternVL3 dynamic tiling, max_num=12, +thumbnail, 256 tok/tile, +~64 text. Tokens = per **sample** = sum over its images.)*

| dataset | median tok | p95 tok | max tok | % >2048 | % >4096 |
|---|---|---|---|---|---|
| CMMD | 6,720 | 6,720 | 6,720 | 100% | 100% |
| bcn20000 | 7,744 | 20,544 | 53,824 | 100% | 87% |
| endo | 143,168 | 319k | 349k | 100% | 100% |
| neojaundice | 832 | 832 | 832 | 0% | 0% |
| iugc (ref) | 320 | 320 | 320 | 0% | 0% |

**Takeaways:** a CMMD pair always needs **>4096** tokens → training `cutoff_len` set to **8192** (was 4096, which would have truncated and corrupted CMMD rows). bcn/endo per-*sample* totals look huge, but **K-chunking bounds images-per-row to ≤K**, so per-*row* load stays within 8192 — the global tile-budget packer is not needed for Phase-1 classification.

## 8. Intra-sample image similarity (how redundant are the multiple images?)
*(2026-06-11 / 0C. aHash 64-bit; similarity = 1 − Hamming/64. ⚠️ aHash is a coarse *global* hash — it misses fine detail like mammography microcalcifications, so it can overstate redundancy for high-res modalities.)*

| dataset | mean similarity | read |
|---|---|---|
| CMMD | 0.899 | near-duplicate views → grouping may add little (but see aHash caveat) |
| bcn20000 | 0.714 | same-lesion multi-shot, partly redundant |
| neojaundice | 0.654 | distinct body regions, **complementary → best grouping candidate** |
| endo | 0.631 | multi-frame, complementary but tiny n |

**Takeaways:** **VRAM is a non-issue** (worst case 15 GB vs 48 GB). The binding constraints are **latency** (1.5× runtime rule) and **context length**. Memory scales with total **tiles**, not image count; `max_num` is the lever.
